Roles

Agreed 20 October 2026

This document defines three separate sets of roles:

  1. Consumer uses: what the datasets will be used for.
  2. API access roles: who may call the API and what each caller can see.
  3. Business roles in the data: the fictional people inside the firm, and what each may do.

1. Consumer uses

Each use reads the same core data. Anything specific to one use goes in a use pack under datasets/<name>/packs/<use>/. A new use adds a pack and does not change the core data.

2. API access roles

Locally, the caller chooses a role with an X-Role header plus a dev key held in the Worker's local secrets file. No key means public.

The API is read-only for every role. You rebuild the data by running the Python generator, not through the API. The plan's admin role is dropped because it would have nothing to do.

3. Business roles in the data (regulatory reporting dataset)

Agreed 20 October 2026

The people who prepare, check and approve the Monthly Balance Sheet Return, and the people who own its source data. They are in the staff table. The return has no approval limits; it has a sign-off chain and data owners.

RoleJob title in the dataDuties
PreparerRegulatory Reporting AnalystRuns the return calculation, sets inclusion and exclusion, prepares the draft. Cannot review their own return.
ReviewerRegulatory Reporting ManagerReviews the draft: reconciliations, movements over 10%, exceptions. Raises mapping amendments.
Mapping and template ownerHead of Regulatory ReportingApproves mapping amendments, dictionary updates and template changes before they take effect.
ApproverChief Financial OfficerApproves the return for submission and approves new return lines.
Data governanceData Governance LeadOwns the field dictionary. Approves source-system schema changes that touch fields the return reads.
Data ownerProduct owners in Technology; Finance Systems AnalystAccountable for one source system and its month-end extract. Requests schema changes.
Credit risk dataCredit Risk Data ManagerReviews customer size classes against filed accounts each year.
Ledger ownerFinancial ControllerOwns the general-ledger control totals.

Separation-of-duties and change rules, which the planted cases test:

  • The preparer may not review the return. The Chief Financial Officer approves it.
  • A schema change to a field the return reads must be matched by a dictionary update before it goes live.
  • A mapping amendment applies from its effective date only, never earlier.
  • Source totals must agree with the ledger within tolerance before the return is reviewed.
